## Section: El problema

Label:

**02 / EL PROBLEMA**

Headline:

**Cuando el negocio crece, el proceso también tiene que evolucionar.**

Copy:

WhatsApp, hojas de cálculo y formularios pueden funcionar perfectamente durante mucho tiempo.

El problema aparece cuando aumenta la demanda y la operación empieza a depender de información dispersa, tareas manuales y personas específicas.

Transformation:

**Manual → Disperso → Difícil de controlar**

becomes:

**Conectado → Automatizado → Visible**

Statement:

**No modernizo por modernizar. Primero entiendo qué funciona y qué realmente necesita cambiar.**

## Section: Servicios

Label:

**03 / SERVICIOS**

Headline:

**Soluciones enfocadas en resultados reales.**

Intro:

**Tres áreas de trabajo, un mismo objetivo: convertir procesos en productos digitales simples, operables y con impacto real en el negocio.**

### 01 — Landing pages conectadas

**Captar un lead es solo el comienzo.**

Diseño y desarrollo landing pages conectadas a formularios, CRM, bases de datos, notificaciones y automatizaciones.

Flow:

**Visita → Formulario → Lead → Automatización → Seguimiento**

### 02 — Sistemas pequeños

**Productos concretos para operaciones concretas.**

Backoffices, CRM específicos, reservas, gestión de eventos, pedidos, inventario y herramientas internas.

Flow:

**Problema → Flujo → Sistema → Operación**

### 03 — Automatización e integración

**Menos trabajo manual. Más control.**

Integro herramientas y automatizo procesos mediante APIs, n8n, webhooks, bases de datos, Sheets, formularios, notificaciones y sistemas existentes.

Flow:

**Sistema A → Integración → Automatización → Datos → Acción / Reporte**

## Section: Trabajo seleccionado

Label:

**04 / TRABAJO SELECCIONADO**

Headline:

**Ideas que ya operan.**

### Case 01

**De operación manual a producto digital operativo**

Category:

**PRODUCT / FULL STACK / OPERATIONS**

Core idea:

A complete product built around a real business operation: flow, interface, backend, database, business rules, deployment, infrastructure, and maintenance.

Insight:

**Construir una interfaz es diferente a hacerse responsable de que el producto completo funcione.**

### Case 02

**Integrar sin invadir**

Category:

**AUTOMATION / APIs / DATA**

Core idea:

Use an independent integration layer to consume authorized data, relate records, sanitize information, store only what is necessary, and generate operational output without unnecessarily modifying the original systems.

Insight:

**No todo problema necesita una migración.**

### Case 03

**Diseñar el sistema que construye el sistema**

Project:

**arcav-ia-flow**

Category:

**AI / PRODUCT ENGINEERING / GOVERNANCE**

Copy:

arcav-ia-flow is Armando's own agentic software-development methodology/tooling.

It separates product, architecture, development, review, QA, DevOps, and automation responsibilities.

Insight:

**No utilizo IA únicamente para programar más rápido. La utilizo para mejorar todo el proceso de construcción de producto.**

## Section: Principios

### Proceso antes que tecnología
Primero entiendo qué ocurre.

### Integrar antes que reemplazar
Conservo lo que funciona.

### Automatizar lo repetitivo
El operador debe ocuparse de lo importante.

### Control sobre dependencia
Prefiero capas desacopladas cuando el contexto lo permite.

### Pequeño no significa improvisado
QA, tests, observabilidad y documentación importan.

### Producto antes que feature
Resolver el problema importa más que completar el ticket.
